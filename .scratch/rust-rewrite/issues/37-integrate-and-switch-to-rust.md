# 37: 全矩阵验收并统一切换 Rust

**What to build:** 维护者可以在全部既定 CPU 能力、语言契约及交付环境验收后，将项目默认构建和 Python 交付统一切换到 Rust。

**Blocked by:** 12: 美式蒙特卡洛；13: 数字期权蒙特卡洛；15: 亚式蒙特卡洛；19: 单障碍 CRR；20: 单障碍数值积分；22: 二元障碍与单边触碰有限差分；24: 现金双边触碰有限差分；26: 双障碍蒙特卡洛；27: 区间累计解析定价；32: 雪球与凤凰有限差分；33: 雪球与凤凰蒙特卡洛；35: 累购有限差分；36: 累购蒙特卡洛。

**Status:** completed

- [x] 以现有公开 API、实现与测试核对完整 CPU 支持矩阵，逐项确认所有产品、引擎、分析操作、默认值、事件边界和历史行为已有等价覆盖。
- [x] 在 Rust 与 Python 公共 API 完成共享契约、输入边界、稳定错误、验证时机、拥有值、失败状态和线程安全验收；拒绝不受支持组合。
- [x] 运行现有适用的 QuantLib 实时对照、结构化支付、收敛、统计与数值回归；参考依赖缺失不得静默跳过，QuantLib 全局设置恢复并正确隔离。
- [x] 验证独立 Rust 消费方无需 Python 即可构建和使用核心；Linux、Windows 与 CPython 3.11–3.15 的普通 wheel 构建、安装、导入及功能测试有实际结果。
- [x] 核对 Python 导出、类型声明、版本信息、源码分发、日历生成流程和第三方数据；更新默认构建、CI 与打包为 Rust，Python 名称仍为 kiyosi。
- [x] 上述验收通过后才统一切换，运行时只使用 Rust 核心；此票保留旧源码供下一票清理，不增加后端切换或兼容层。
- [x] 记录实际执行的检查与未验证环境；不以 Linux 单一环境结果代替完整矩阵，不新增性能基线、速度报告或回归门槛。

## Comments

- 完整产品/引擎清单、共享契约、数值依据、实际环境与限制见 [Rust 集成验收记录](../../../docs/rust-acceptance.md)。新增公共分派验收涵盖 32 个导出引擎、22 个合约样例及 61 个支持组合；不支持组合在定价、Greeks 和隐含波动率入口按原生转换拒绝。
