# 使用 Rust 重写 kiyosi 核心并迁移 Python API

Status: ready-for-agent

## Problem Statement

kiyosi 的维护者希望以 Rust 作为项目的长期维护语言，改善代码组织与可维护性，同时继续为 Python 用户提供 Black–Scholes–Merton 模型下的衍生品定价能力。当前领域语义、数值引擎和验证逻辑由 C++ 核心定义，Python 通过原生绑定调用；项目还交付独立 C++ 库和可选 CUDA 后端。

这次重写需要覆盖现有 CPU 功能及其完整行为契约。仅替换部分算法或使正常输入得到相近价格不足以完成迁移：默认值、事件边界、历史记录、错误类别、验证时机、失败状态保证、线程安全以及 Python 输入协议都影响用户的正确使用。

此次工作的主要目标是 Rust 化和可维护性。定价准确性是硬约束，性能收益与性能回归不作为本次验收条件。

## Solution

采用 Rust 核心与独立的 PyO3 绑定 crate，由 Rust 核心独占领域语义，对外提供惯用的 Rust API 和 Python API。Rust 核心可独立构建、测试和使用，无需 Python 或绑定框架。Python 包继续使用 `kiyosi` 名称，采用 maturin 打包，覆盖 Linux、Windows 和 CPython 3.11–3.15 的普通 wheel。

完整迁移现有 CPU 产品、产品与引擎支持组合、Greeks、隐含参数求解、市场输入、交易日历、观察日程和历史记录。沿用现有数值算法，不新增产品或算法。保留 Python 的主要使用方式，允许为清晰性调整 Alpha 阶段接口，不承担公开 C++ API 兼容层。

分阶段实现并验证，完整验收后统一切换。迁移期间保留旧实现用于行为对照，并使用独立 QuantLib 对照、收敛和统计正确性检查约束结果；最终交付仅运行 Rust 核心，删除旧 C++、CUDA、绑定及相关构建配置。

## Implementation Decisions

- **领域核心与绑定分离。** 使用 Rust workspace，分别设置领域核心 crate 与 PyO3 绑定 crate。领域模型、规则、状态转换、不变量、默认值、选择值和验证仅由核心定义；核心独立构建与测试不得探测或依赖 Python。Rust API 使用惯用类型和错误表达，Python 绑定仅处理语言边界。
- **保留既有 CPU 支持矩阵。** 覆盖所有现有 CPU 产品与引擎组合，以及 Greeks、数值敏感度、隐含波动率、隐含票息和相关结果元数据。产品支持不代表任意引擎均受支持，不扩展组合。迁移前以现有公开 API、实现和测试核对清单，防止仅按概括性产品名称判断完成度。
- **沿用数值方法。** 保留现有解析公式、近似、二叉树、数值积分、有限差分和蒙特卡洛方法及其适用边界，不借重写切换模型或增加算法。精度与统计正确性优先；与独立正确性证据冲突的既有行为须单独确认，不以复刻旧错误作为验收目标。
- **默认值只有一个来源。** 在 Rust 核心定义并测试领域默认值，Python 关键字默认值从核心派生。等价输入、状态和配置下，两种语言的领域接受范围、结果、边界行为、验证时机、错误类别和失败状态保证保持一致。
- **严格适配 Python 输入。** 保留数值、整数协议、日期时间、iterable 和原生包装对象的既有输入契约，不依赖 PyO3 默认转换恰好与原绑定一致。拒绝意外有损转换，包括隐式 bool 到数值、非整数到整数以及目标表示范围外的值。选择字符串优先使用 Python `snake_case` 并映射到核心选择值。
- **区分错误来源。** Python 表示、协议和签名违反使用语言原生异常；领域拒绝使用具有稳定类别的结构化核心错误，Python 暴露可检查类别的领域异常，调用方无需解析消息。类型或签名排除的组合可在 Rust 编译或 Python 转换阶段失败；可以表示但不受支持的组合必须由核心返回领域错误。资源耗尽与内部失败保留语言原生语义，并记录 Rust 与 Python 的操作失败映射，不将其统一伪装成领域拒绝。
- **提交前验证与拥有值。** 构造、替换及历史更新在提交有效状态前执行核心领域验证；适配层预检查不能替代核心验证。维持拥有值优先、既有只读属性和返回新值的替换语义，避免引入不必要的借用视图或改变失败后的原对象状态。
- **市场、日期与事件语义完整迁移。** 保留期限结构、计息与年化规则、日期时间解释、交易日调整、观察日程、到期与事件边界、历史事件和缺失历史语义。保留核心自定义交易日判断能力及其确定性和线程安全约束；Python 自定义日历继续采用已有显式开闭市覆盖能力，不新增 Python 回调接口。
- **仅交付 CPU 执行后端。** 移除 CUDA 能力、相关运行库和内核，不保留 CUDA 桥接层。保留 CPU 线程配置、伪随机、Sobol、对偶变量、路径数语义和适用的统计结果。固定 seed 不承诺与旧 C++ 随机流或数值结果逐位一致，但不得削弱既有 CPU 线程数无关的可复现性契约和声明范围。
- **保留并发与同步契约。** 在 Rust 公共 API 文档中明确库级线程安全默认值，以及不同实例、共享实例和并发修改的例外。保留按调用限制 CPU 并发度的语义，避免通过进程全局可变设置影响其他调用。Python 计算期间仅在核心线程安全契约满足时释放 GIL；释放期间不访问 Python 对象、执行 Python 回调或操作依赖 GIL 的状态。保持现有同步、信号处理和无取消接口的行为，并记录操作失败映射。
- **Python 打包与平台。** 使用 maturin 构建 PyO3 扩展，Python 包名继续为 `kiyosi`，保留主要使用方式和模块职责。按 CPython 版本构建普通 wheel，覆盖既有 Linux、Windows 交付平台及 CPython 3.11–3.15；不新增架构或解释器类型。绑定导出、类型声明、版本信息、源码分发、测试依赖和第三方声明同步适配。独立 Rust 核心不得因工作区默认配置而要求 Python。
- **Alpha API 可调整。** 提供惯用 Rust 与 Python 接口，允许为清晰性调整 Alpha 阶段 API；不为旧 C++ 接口提供兼容层。接口调整不得成为遗漏现有领域能力或削弱领域契约的理由。
- **分阶段实现，统一切换。** 迁移期间保留旧 C++ 实现作为对照，在彼此隔离的进程或环境中比较两套同名 Python 包，不增加用户可见的双实现选择开关。逐项完成 Rust 功能和相应测试，所有范围与正确性要求通过后才切换交付。
- **完成所有关联迁移。** 同步迁移或调整交易日历生成工具、测试及其数据格式、类型声明生成、版本来源、CI、构建测试说明和仓库工作约定。保留 Sobol 等第三方数据及其许可声明。验收后删除旧 C++、CUDA、绑定与其专用构建和分发配置，清理失效依赖及引用。
- **不设性能门槛。** 本次不要求提速、性能基线、Rust/C++ 耗时对比报告或性能回归阈值。性能回退不单独阻止验收；数值精度、统计质量、验证、所有权和并发正确性要求保持有效。

## Testing Decisions

- **已确认的测试边界。** 以现有 Python 公共 API 为主要端到端边界，在 Rust 公共 API 测试等价领域契约。复用现有构造、定价、Greeks、求解、日历、历史与替换接口，不新增仅为测试服务的公开入口。用户已明确确认该边界。
- **测试外部行为。** 断言公开返回值、结构化错误类别、验证时机和失败后状态，避免绑定私有布局、内部调用次数、线程池实现、消息逐字内容或新旧随机序列逐位一致。已有语义案例应迁移其业务断言，而非照搬 C++ 实现细节。
- **完整支持矩阵验收。** 对现有 CPU 产品与引擎组合建立覆盖清单，并验证不受支持的组合按契约失败。覆盖价格、可用 Greeks、数值敏感度、隐含参数、统计结果和适用边界；迁移现有数值回归案例，而非只运行正常输入的冒烟测试。
- **跨语言契约场景。** 延续现有原生与 Python API 契约测试做法，在 Rust 和 Python 分别验证等价的领域默认值、有效与非法输入、事件边界、历史状态、参数可识别性、错误类别和失败状态保证。语言表示不能表达的输入只在适用语言测试，不强行制造等价性。
- **Python 边界场景。** 沿用已有严格转换与 API 测试，覆盖 bool、整数协议、整数范围、非整数转换、日期时间及既有时区处理、选择字符串、iterable、默认参数、只读属性、拥有值和替换。验证绑定默认值来自核心，并检查导出与类型声明的一致性。
- **独立定价对照。** 继续通过公开 Python API 与实时 QuantLib 比较价格、Greeks 和隐含波动率恢复；沿用已固定的 QuantLib 测试依赖和测试中的市场、日期、日历约定。需要参考库的测试不得在缺少依赖时静默跳过。QuantLib 仅为测试依赖，不成为核心或用户运行依赖。涉及 QuantLib 全局估值日期的测试恢复设置，并串行运行或采用独立进程隔离。
- **收敛与结构化支付。** 延续现有美式网格细化、差分步长稳定性、结构化产品终端支付组合和有限差分收敛检查，验证到期、观察日、障碍事件、历史记录、零剩余期限以及既有非有限值或溢出回归场景。参考不确定性与被测引擎误差预算分开控制。算术亚式的近似对照验证相同近似，不将其表述为真实算术平均价格的精确参考。
- **蒙特卡洛与统计契约。** 沿用已有伪随机、Sobol、对偶变量及线程相关案例，验证路径数与边界、seed 可复现性、跨 CPU 线程数一致性、早期终止下的采样语义和适用的标准误差、置信区间。新旧实现比较按适用的数值容差、统计准则和独立参考，不要求随机流相同，也不放宽现有正确性预算来掩盖回归。
- **并发与生命周期。** 通过公开 API 验证契约允许的共享实例和不同实例并发调用、返回值生命周期、替换失败后的原对象有效性以及 Python 并发结果正确性。保留 GIL 与同步行为的检查意图，不以线程加速比作为通过条件，不执行契约不允许的数据竞争。
- **生成工具与第三方数据。** 迁移现有交易日历生成工具的测试，使输出及其消费方式适配 Rust；验证领域日期数据与生成结果一致，并保留所使用第三方数据的许可信息。
- **构建、安装与交付。** 在无 Python 参与的条件下验证核心独立构建、测试和消费；在 Linux、Windows 及 CPython 3.11–3.15 矩阵验证 Python wheel 的构建、安装、导入及测试。检查最终产物不依赖被删除的 C++/CUDA 实现或 CUDA、oneTBB 专用运行库，版本信息与类型声明可正常消费。
- **分阶段对照与最终门槛。** 旧实现对照仅是证据之一，独立参考和领域不变量同样必需。完整 CPU 功能清单、上述正确性与契约测试、独立核心构建及既定交付矩阵均通过后，才可删除旧实现并统一切换。测试记录须区分实际执行通过与未能验证的环境，不以一个 Linux 开发环境的结果代替 Windows 或全部 Python 版本验证。
- **性能检查排除。** 不新增性能基线、性能回归测试或速度阈值；若现有测试工具混合计时和正确性断言，保留正确性部分，不把耗时比较作为本次验收条件。

## Out of Scope

- 公开 C++ API、C ABI 或其兼容层，以及保持旧 C++ 源码、头文件或构建消费方式的兼容性。
- CUDA、其他 GPU 后端、CUDA/C++ 计算桥接层和运行时双实现选择开关。
- 新产品、新模型、新算法、新增产品与引擎组合，或与语言迁移无关的功能扩展。
- 新增 Python 回调、异步计算、取消接口、信号轮询或其他并发功能。
- 新增平台或架构、自由线程 Python 发行版、ABI3 wheel，以及 CPython 3.11–3.15 之外的交付扩展。
- 保证与 C++ 相同的随机序列、跨实现逐位一致的浮点结果，或保留已确认违背正确性要求的旧行为。
- 性能优化目标、性能回归调查门槛、性能基线和性能比较报告。
- 为未来场景增加抽象层、后端扩展框架或多余配置。
- 自动发布正式版本、发布 Rust crate 或修改仓库之外的文档站点；这些不是完成本规格的必要交付动作。

## Further Notes
