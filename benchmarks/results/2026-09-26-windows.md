# Benchmark report: Windows CPU, 2026-09-26

Kiyosi used less median CPU time in 22 of the 23 paired QuantLib cases in this run. Ratios ranged from 0.68x for American Bjerksund–Stensland to 16.03x for European Monte Carlo. These are comparisons of the configured implementations, not accuracy-normalized speedups or evidence of a performance change from an earlier revision.

## Run and provenance

- Recorded start: `2026-09-26T13:52:16+08:00`.
- Source: `build/windows-benchmarks/benchmarks.json`, preserved unchanged as [raw Google Benchmark results](2026-09-26-windows.json).
- Windows x64; AMD Ryzen 9 5900X 12-Core Processor. The result records 24 logical CPUs and 3,700 MHz per CPU; the CPU model was read from the reporting machine.
- Local build cache: MSVC `19.51.36257.0`, Ninja, Release (`/O2 /Ob2 /DNDEBUG`), static MSVC runtime, vcpkg `x64-windows-static`, CUDA disabled.
- Google Benchmark `v1.9.5`, release build (recorded in the JSON). The installed QuantLib CMake package referenced by the build cache reports **1.42.1**, rather than the 1.43 suggested in the benchmark guide.
- Five repetitions per case, one benchmark thread; 61 cases total: 33 Kiyosi matrix cases, 23 QuantLib counterparts, and five standalone Monte Carlo cases. No benchmark error rows were recorded.
- Repository HEAD when preparing this report: `604f90384f47f9c3665b2a14bd303eaa9816c003`. The result does not embed a source revision, compiler, or QuantLib version, so the local environment details above are supporting metadata, not an independently recorded identity of the executable.

## Method

The [benchmark guide](../README.md#scenario-and-interpretation) describes the fixed market and contracts. The matrix uses spot and vanilla strike 100, rates 4% and 1%, volatility 20%, and a one-year term from 2025-01-01. CRR uses 128 steps; finite difference uses 80 time and 80 asset steps. Vanilla Monte Carlo uses 5,000 Kiyosi paths versus 2,500 QuantLib antithetic sample pairs, with 10 European or 20 American steps; structured Monte Carlo uses 2,000 paths. The seed is 42.

Construction precedes the pricing loop. Kiyosi calls `price()` and QuantLib calls `recalculate()` followed by `NPV()` to avoid cached valuations. Prices in the comparison are warmup counters. The matrix table below is generated by `compare.py` from median **CPU time** in nanoseconds; a ratio above 1 means Kiyosi took less time. The separate large Monte Carlo table uses median **wall time**, matching its `UseRealTime()` registrations.

## Interpretation

- European analytic pricing took 100.4 ns versus 1,349.7 ns (13.44x), with a price difference near floating-point roundoff. American CRR took 7,847.4 ns versus 87,886.7 ns (11.20x).
- American Bjerksund–Stensland was the only paired case where Kiyosi took more time: 5,156.2 ns versus 3,529.6 ns. Its price delta was 0.031851; Kiyosi implements the 2002 approximation and QuantLib the 1993 approximation.
- The largest absolute paired price delta was European Monte Carlo at -0.0726075. European finite difference differed by -0.0698726 and barrier finite difference by -0.0679342. Timing ratios alone do not establish comparable numerical accuracy; grids, integration, random sampling, and American regression differ.
- One-touch comparisons price two QuantLib binary barrier contracts. No single aggregate speedup is reported across these different workloads.
- Kiyosi-only rows have no direct QuantLib counterpart in this harness; `n/a` is not a zero time or a failed case. No CUDA or Python binding performance was measured.

## Reproduce

From the repository root on Windows, with QuantLib installed through vcpkg:

```powershell
.\run-benchmarks.bat C:\path\to\vcpkg
python benchmarks/compare.py build/windows-benchmarks/benchmarks.json
```

The runner activates the Visual Studio Developer environment and builds Release. To regenerate only this report's matrix table from the archived run:

```powershell
python benchmarks/compare.py benchmarks/results/2026-09-26-windows.json
```

Use the recorded dependency versions and comparable hardware for a meaningful comparison. Re-running the current source or a different installed QuantLib version is a new measurement, not a reconstruction of this snapshot.
